Set up photo delivery through the Pi

With the Pi, guests can save finished photos directly to their phones over the booth Wi-Fi. The guest network does not need internet. The owner sets up the station, pairing and guest access.

Pi photo delivery is built and installed on our test station. It is still disabled in TestFlight. Release awaits a test with an iPad and guest phone on the Pi Wi-Fi. An owner download will follow after that acceptance.

  1. What you need

    The owner needs a Raspberry Pi 3 running supported Debian Bookworm or Trixie on an OS dedicated to the booth. A printer is optional.

  2. Prepare the Pi

    On the existing Pi, explicitly choose photos-v2 in the installer. It preserves the station configuration; it is not an SD-card clone. The first technical setup over SSH is covered separately in the technician guide.

  3. Pair the station

    On the iPad, open Setup → Devices → Print station to enter this station’s private pairing code. Pi photo delivery is a separate section under Setup → Pi photo delivery. Do not share the code with guests.

  4. Enable an event

    Turn on QR photo download for the event and choose Pi server under Photo delivery. Guests see Wi-Fi credentials only if the owner explicitly enables guest access.

  5. Save a photo and end the event

    Guests join the Pi Wi-Fi (no internet is needed), scan the second QR code for the photo and tap Save. At event end, the owner unlocks the operator area so the app can revoke Pi copies. If the Pi is offline, deletion stays pending until it reconnects. Photos already saved on phones cannot be recalled.

Network and privacy

  • Uploads from the iPad to the Pi use pinned TLS; local guest downloads use HTTP on the Pi Wi-Fi. No internet is required.
  • An iPad with cellular service may still have internet over cellular while connected to the Pi Wi-Fi. Verify this on the actual device.
  • A direct Pi-to-Mac Ethernet cable without DHCP is for maintenance only; it does not provide internet to the Pi or guests.
  • Event-end revocation is the primary cleanup. A seven-day expiry is best effort only and depends on the Pi clock working.

If something goes wrong

The app reports a different or mismatched station
Do not transfer photos. The owner must check and repair the station pairing. Then start a new event; reusing the same event ID is not a repair.
The station stays “Checking” or no photo QR appears
The Pi must be reachable and confirm the photo before a QR appears. Check that the iPad and Pi are on the intended local network; ask the owner if it keeps waiting.
The iPad cannot reach the Pi on the local network
Allow the app to access the local network and connect the iPad to the Pi Wi-Fi. Internet access is not required.
Pi copies remain after the event ends
Unlock the operator area and reconnect the Pi. The app must confirm the pending deletion. Copies already saved on phones cannot be deleted.
